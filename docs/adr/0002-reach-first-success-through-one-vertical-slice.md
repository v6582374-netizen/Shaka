# 通过一条纵向闭环抵达首次可信成功

当前仓库已经具备标准起始状态、调用证据记录与完整性检查、多模态评估和人工审校，但这些能力尚未被一个真机调用生命周期串联。最短实施路线是先完成一个本地纵向闭环，再让编程智能体在冻结边界内选择候选方法；不按模型类别预建平行基础设施。

## 实施顺序与验证门

1. **调用运行器**：实现一个本地入口，按固定顺序执行 `就绪检查 → 开始记录 → 运行一个候选 → 释放控制权 → 完成证据 → 自动评估 → 复位或停止`。运行器只编排现有契约，不包含策略逻辑。
2. **零写入端到端门**：使用真实相机和机器人状态运行完整链路，但禁止发布执行命令。退出条件是候选输入、动作维度与关节顺序正确，记录覆盖完整生命周期，评估器能读取工件，且唯一控制入口确认没有竞争发布者。失败时只修接入或记录，不进入真机尝试。
3. **单回合金丝雀门**：选择当前证据支持的最简单候选，通过唯一控制入口执行一次低速、单次尝试。`aborted`、记录不完整或评估器失效立即停止；部署缺陷退回零写入门，候选行为失败则保留证据并进入下一项假设。
4. **预算内自主研究**：人只设置总真机回合数和机器人运行时间。编程智能体可以选择或组合 UniFoLM、行为克隆、真实世界强化学习、启发式和代码策略；每项假设绑定父候选、单一修改、子预算、诊断指标和回退点，并重新通过候选准入门。
5. **首次可信成功终点**：自动结果为 `succeeded` 时立即暂停研究，由人检查原始视频。确认指定食指接触黄色按钮并随后撤离后，本路线完成；安装验收和可靠性提升转入独立后续工作。

## 回退与停止规则

- 静态检查、离线回放或零写入失败：拒绝候选，修复同一接入缺陷，不消耗真机回合。
- 金丝雀出现部署缺陷：回到零写入门；出现候选行为失败：回到父候选并启动新的单一假设。
- 一个实验分支耗尽自己的子预算、未达到预先声明的诊断改善或低于父候选：停止该分支并恢复父候选；不设置跨方法统一的固定失败次数。
- 自动结果为 `failed` 或 `indeterminate`：保存证据，完成自动复位后才能开始下一次独立调用。
- 出现 `aborted`、总预算耗尽、复位失败、证据链失效、评估器失效、竞争命令发布者、冻结契约被修改或候选绕过唯一控制入口：停止整个自主研究。
- 人工确认首次可信成功：停止当前 0→1 路线，不继续为可靠性、泛化或平台化追加投入。

该顺序以最早产生端到端物理证据为优化目标。离线工作只用于避免无信息量或不可归因的真机回合，不能成为无限延迟真机验证的替代品。
