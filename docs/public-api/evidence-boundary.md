# 证据边界与真机闭环

Shaka 同时拥有确定性软件案例与 G1 物理金丝雀。两者回答不同问题，必须分别陈述。

## 公共 API 证明什么

- 外部应用能够稳定调用；
- 请求校验、五态结果、动作计划、逐阶段轨迹和证据摘要具备完整形式；
- 正常、遮挡、保护拒绝和初始位姿变化分支可复现；
- Qwen3-Max 的两次真实百炼调用、上下文、结构化计划、Request ID 和 token 用量已脱敏留存；
- manifest 绑定全部 JSON 工件，只读验证器会重放两轮结果并核对反馈映射、三种反馈策略和凭证边界。

公共 API 默认返回 `evidence_level=illustrative_simulation` 与 `physical_execution=false`。其中的 `succeeded` 只表示确定性软件任务通过，不能解释为 G1 物理成功。

## G1 物理金丝雀证明什么

仓库公开保留运行记录摘要与历史执行代码。它们支持以下事实：

- 接入真实相机与机器人状态；
- 辅助主机经 `eth2` 和 `rt/arm_sdk` 进入真实控制链；
- BrainCo 收到左右手新鲜命令流；
- 实时力矩安全门参与物理执行；
- 中止原因已进入后续问题归因。

V7 的轨迹进入机器人后触发 4 N·m 上身安全门。V8 的右肩滚转通道测得 16.625 N·m，高于 12.5 N·m 门槛。两次都由安全门中止，均未记录为任务成功。

因此，当前正确结论是：**G1 真机端到端链路已经验证，真实控制链与安全拒绝机制有效；当前绝对位姿 VLA 输出仍无法适应实时力矩反馈，任务效果未过关。**

公开仓库目前没有完整发布 V7/V8 的原始相机观测、力矩遥测、BrainCo 日志、执行回执或视频，因此这些材料不能被描述为可由外部独立复核的完整物理证据包。

## 当前证据不证明什么

- 未证明黄色按钮任务已在真实 G1 上可靠成功；
- 未证明安全门覆盖全部风险，只证明相应门限在 V7/V8 中真实生效；
- 仿真指标不能替代接触动力学、相机噪声或真机保护证据；
- 固定案例中的软件改善不能外推为真实机器人成功率、跨场景泛化或长期自治；
- 两次物理金丝雀不足以形成统计意义上的可靠性结论。
- 尚未完成“真机拒绝 → 新策略修订 → 再次真机验证”的物理反馈周期。

## 从软件调用到物理执行的分层

1. **确定性软件案例**：验证契约、生命周期、反馈修订和证据回放。
2. **零写入真机观测**：验证真实感知、机器人状态、记录和安全检查链。
3. **监督物理金丝雀**：在唯一写入口与实时安全门下验证控制通道和物理响应。
4. **可靠任务成功**：下一阶段需要在线力矩适配、高保真动力学预演和跨条件重复。

请求契约、五态输出、独立评价、证据摘要和客户端调用方式跨层保持稳定；每提升一个证据等级，都必须新增该层独有的观察、授权和拒绝机制。
