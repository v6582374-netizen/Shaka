# 系统架构与创新

Shaka 的核心是 Qwen 负责提出与调整计划、确定性程序负责执行和裁决，二者不能互相越权：

```text
科学问题与冻结条件
  ↓
Qwen3-Max 第一轮计划
  ↓
结构校验 → 契约执行 → 模型外阈值判断
  ↓
第一轮原始结果与反馈 → Qwen3-Max 有界调整
  ↓
第二轮动作计划执行 → 同口径判断 → manifest、摘要与脱敏回执
```

## 四个架构创新

### 1. 同一契约跨越无硬件与有硬件环境

评委调用、契约仿真、零写入 G1 观测和未来受监督真机执行共享输入输出语义。当前代表案例只到契约仿真层；硬件迁移仍需真实校准、动力学、保护部署与现场授权。

### 2. 把动作完成与任务成功分离

候选不能自行宣布成功。独立评估器只读取完整证据，输出 `succeeded | failed | indeterminate | aborted | abstained`，避免把“命令发完”偷换成“任务完成”。

### 3. 动作控制量进入执行器，而非停留在解释层

第二轮只允许改变 `observation_duration_ms`、`approach_scale` 与 `motion_duration_scale`。三者分别改变观察路点时长、接近/接触关节增量和运动时标，因此 Qwen 输出可直接在四路点动作计划中观察，而不是装饰性文本。

### 4. 证据先于平台

系统以版本化文件、摘要和单次调用记录形成可审计链路，不依赖数据库、消息总线或复杂工作流。结构足够支撑未来扩展，但首版没有平台税。

### 5. 物理保护是唯一写入口的属性

候选、智能体和前端都不能绕过机器人侧守护。保护拒绝本身也是结果和证据，而不是被 UI 隐藏的异常。

## 发展潜力

同一边界可逐步承载多技能、多机器人并行假设检验、跨任务经验复用、世界模型辅助预检与真实世界强化学习；这些能力可以在出现真实重复后演化，而无须推翻当前 API。
